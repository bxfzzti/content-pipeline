# polishing-writing

接收正文 → 跑四层自检 → 输出质检报告 + 修改建议。**只检查，不改正文。**

## ⚠️ 质检Agent已升级为独立prompt（2026-06-17）

完整的质检Agent prompt已独立为 `references/quality-agent-prompt.md`（v3）。

**核心升级：**
- L0 结构对照（对照结构Agent输出）
- L1 硬性规则（禁用词、设问句、反模式、事实核查、禁用标点）
- L2 风格一致性（标题、开头、节奏、口语化、结尾）
- L3 内容质量（观点支撑、支柱类比、数据密度、信息来源多样性）
- L4 活人感终审
- L5 平台适配（小红书300-800字/公众号1500-3000字/抖音200-500字）
- 读者体验模拟 + 删减建议 + 严重程度量化（致命/严重/中等/轻微）
- 最多迭代3轮，连续2轮无新增问题停止

- 修复Agent（`fix-agent-prompt.md`）：接收质检报告，按严重程度排序修复

本skill（polishing-writing）保留为**快速自检**用途，完整质检请用质检Agent prompt。

## L1 硬性规则

**⚠️ 官网优先铁律（2026-06-10/11教训）：** 价格、核心参数必须去官网确认，不能采信搜索引擎二手信息。质检发现「错误」时，先确认验证来源是否比文章来源更权威——如果文章写的是官方发布会价格，而你搜到的是媒体转引，应该是你让步。详见 `references/fact-check-cases.md` 案例4。

**禁用词扫描：**
- "说白了" → 换成"其实就是"或直接说结论
- "意味着什么" / "这意味着" → 直接说结论，不设问
- "那结果会怎样呢？" → 直接说结论或删掉（也是模板词）
- "本质上" → 换成"说到底"或"其实"
- "换句话说" → 删掉，直接说
- "翻译一下" → 删掉前缀，直接说那个意思
- "这事儿的逻辑是这样的" → 直接讲逻辑，不要预告
- "不是xxx，是xxx" → 改成不工整的口语
- "但有一件事已经变了" → 直接写那个变化，不要预告
- "这件事的讽刺程度，怎么说呢" → 直接吐槽，不要预告
- "不可否认" / "综上所述" / "总的来说" → 删掉或换成具体回扣句
- "首先...其次...最后" → 换自然转场

**禁用标点：**
- 冒号段落 → 换成逗号句号
- 破折号开头 → 融入句内
- 双引号"" → 换成「」或直接不加

**结构套话：**
- "让我们来看看" / "在当今...的时代" → 删
- 连续bullet point超过3个 → 改成散文
- 大段加粗超过2行 → 过度结构化

**模板词频检查（最多命中1个）：**
- "这就很有意思了""结果是什么？""往大了说""坦率的讲""怎么说呢"
- **设问句模板**（"这意味着什么"/"那结果会怎样呢"/"什么概念"/"对xxx意味着什么"）— 同一篇文章中这类设问最多出现1次，超过则改用陈述句直接说
- **过渡模板**（"翻译一下"/"这事儿的逻辑是这样的"/"不是xxx是xxx"/"但有一件事已经变了"）— 出现即标记，参照 khazix-style 的活人感替换表

**新文体反模式扫描（2026-06-16 实测4篇ES8文章教训）：**

这些是卡兹克风格的残留，新文体下必须删除或改写：

| 反模式 | 示例 | 修复方式 |
|--------|------|---------|
| **设问引导** | "你有没有发现一件事" "我好奇的是" "他们去哪了" | 删掉设问，直接陈述 |
| **设问过渡** | "为什么？" "这意味着什么？" | 删掉，直接说原因/结论 |
| **虚拟对话** | "你说X5L是豪华品牌，品牌溢价在那里" | 改成陈述句 |
| **排比式总结** | "X5L输在代差。M9输在价格。" | 改成不工整的口语 |
| **煽情式收尾** | "这可能是中国汽车工业历史上最有里程碑意义的突破" | 轻轻收，不升华 |
| **连续设问** | "为什么？为什么是它？为什么是现在？" | 改成陈述句 |
| **"有人说"引入** | "有人说等BBA纯电成熟会逆转" | 直接说你的判断 |

**检测方法：** 逐句扫描，问自己「这句话是在说事，还是在安排读者？」如果是后者，改掉。

**工具名检查：**
- "AI工具""某个模型""相关技术"等空泛表述 → 改成具体名称

## L2 风格一致性

**开头：**
- 是否从具体事件/场景切入？（不是宏大叙事）
- 第一句是否有"然后呢"的冲动？

**节奏：**
- 是否有长短句交替？（连续3句以上长度相近=呆板）
- 是否有一句话独立成段？（全文3-5次最佳，超过5次=AI味）
- 偏离主线的段落后面有"扣主线句"拉回来吗？
- 有用疑问句制造节奏刹车和转向吗？

**口语化：**
- 使用了多少个不同的口语转场？（至少8-10个）
- 有真实的口语感吗？（不是刻意打断，是自然说话的方式）
- 有至少一处自嘲或承认不足吗？
- 标点用来表达情绪了吗？（"。。。""？？？"至少出现一种）

## L3 内容质量

**观点支撑：**
- 每个观点有具体的人/场景/细节/数据支撑？
- 有没有空泛的论断没有例证？

**知识输出方式：**
- 知识点是否以"聊着聊着顺手掏出来"的方式呈现？
- 有没有"下面我来介绍"这种教科书式科普？

**支柱类比检查（2026-06-15新增）：**
- 文章有没有一个贯穿全文的支柱性类比/事实/参照物？（如丰田之于零跑、开车上高速之于李斌预警）
- 每个大段落是否都回拷了核心论点？删掉任何一段不影响核心论点成立→它不该出现
- **⚠️ 有标题但没有支柱→观点堆砌，退回 framing-article 重找支柱**

**跨域类比：**
- 有没有至少一个跨域类比？（用另一个行业/生活场景解释当前话题）
- 这个类比是不是从生活里来的，不是从知识库里来的？

**对立面理解：**
- 在讲核心观点时，有没有对对方立场的理解和承认？
- 先站到读者处境里，再给出自己的视角？
- **⚠️ 2026-06-15 教训：** 批评一个组织/公司时，必须加一句承认对方可能的真诚立场（如「公平地说，他可能是真心在做X」），否则文章显得偏激。这句话放在批评段落中间，不是开头也不是结尾。

## L4 活人感终审

通读全文，回答：

- 文中的情绪表达是体感记忆（"我当时就愣住了"）还是知识性描述（"我非常震撼"）？
- 这篇文章有只有你才能写出来的角度吗？换个人能写差不多的吗？
- 语气是不是"一个有见识的普通人在认真聊一件打动他的事"？
- 从头到尾读，有没有哪里注意力断掉了？
- 全文独立成段的句子有没有超过5处？超过则合并
- 转场是否隐形？读者能记住你用的某个转场词吗？能→太显眼了

## L5 飞书排版检查（发布前必过）

**⚠️ 2026-06-15 教训：** 文章全篇没有 `##` 二级标题，发布到飞书后 42 个 block 全是普通段落，没有章节分界。

**核心原则：格式服务内容，不是数数达标。**（2026-06-15教训：用户指出排版检查不是数`##`有几个，而是当内容需要强调或分段时才用格式）

排版检查不是数 `##` 有几个，而是问自己：

1. **需要着重体现某一句话吗？** → 用 `>` 引用块（publish_to_feishu.py 转为斜体+「」包裹）
2. **需要对某个段落做小标题提炼吗？** → 用 `##` 二级标题（转为 H2）
3. **段落之间需要呼吸感吗？** → 用 `---` 分割线

**自检方法：**
- 读一遍文章，问自己「这段讲的是什么？」如果答不上来，说明需要加 `##` 标题帮读者定位
- 找全文最有冲击力的 1-2 句话，用 `>` 引用块强调
- 如果全文一马平川全是段落没有任何格式标记 → ❌ 需要加格式

**禁止：**
- 全篇只有 `#` H1 标题没有 `##` H2——飞书文档会变成一堵墙
- `<callout>` `<grid>` `<text>` 等 Lark 扩展标签——会存为纯文本

**L4 活人感** ✅/❌

## 数据流：Skill 之间的数据传递

```
【消费】完整正文 markdown（来自 writing-draft）
【产出】质检报告（L1-L4逐层结果 + 修改建议）
【本地】/tmp/article-pipeline/05-quality-report.md
【Obsidian】~/Documents/Obsidian/汽车行业/流水线/05-quality-report.md
【转发】→ writing-draft（不通过时，退回修改）
          → publishing-doc（通过后，用户说「发」时）
【依赖】writing-draft（必须先有正文才能自检）
```

## 边界

**不做：** 修改正文、排版、发布。输出报告后等待用户指令：
- 「按这个改」→ 在正文中执行修改建议
- 「改好了，再查」→ 重新跑自检
- 「发」→ 调用 `publishing-doc`
