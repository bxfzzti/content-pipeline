# 内容创作流

**从今天写什么，到一篇有依据的内容。**

把素材、选题、角度、写作和质检连起来。每一步都有输入、产物和确认点。

[项目介绍](https://bxfzzti.github.io/content-pipeline/) · [个人项目集](https://bxfzzti.github.io/) · [完整技术说明](README.technical.md)

</div>

## 可以做什么

- **先找到值得写的题**：热点与产品体验分开整理，保留来源与数据状态。
- **把判断放在写作前**：代码预筛和模型判断分工，在选题、角度、定调处确认。
- **写完也能回看**：质检、内容适配、飞书沉淀与可选知识库组成后续链路。

## 怎么开始

1. 读取article-pipeline/SKILL.md总入口，检查需要的数据源与工具。
2. 告诉Agent本次方向，先看候选题及原文来源。
3. 确认选题、角度和定调后，再推进正文与发布。

把下面的说明交给支持读取仓库的 Agent：

```text
请读取 https://github.com/bxfzzti/content-pipeline 的 article-pipeline/SKILL.md 及当前阶段引用。先检查可用的数据源和依赖；帮我整理今天值得写的选题，保留来源、数据时间和不可用项，等待我确认，不要直接写稿或发布。
```

## 当前范围

这是需Agent与数据源配合的工作流，不是打开网页就能自动出稿的服务。来源可能实时不可用；缓存必须标注。飞书发布和本地知识库需单独配置。

## 数据与隐私

公开介绍页不连接任何个人账号。实际流程禁止借用个人小红书登录态，发布前保留确认。

## 开发与进一步说明

完整工作流入口为[article-pipeline/SKILL.md](article-pipeline/SKILL.md)。热点与选题、角度、定调三个确认点保留；数据源、模型和飞书等依赖按环境配置。本次公开部署仅为site/介绍页，不运行抓取、写作或发布。
