# 独立质检系统

## 设计思路

质检和写作必须分离。写作者天然对自己的文章有确认偏误，需要一个独立的「审稿人」视角。

## 执行方式

用 `delegate_task` 派一个子agent，传入：
1. 完整正文
2. 定调和论点结构（来自 framing-article）
3. 质检prompt（对抗式审稿人角色）

子agent以「挑剔的编辑」身份审稿，只找问题，不夸文章。

## 质检prompt模板（动态领域）

根据文章领域调整审查者角色，不要硬编码为「汽车编辑」：

- 汽车/车型文章 → 「资深汽车编辑」
- AI/科技行业文章 → 「资深科技编辑」
- 消费品/好物文章 → 「资深消费电子编辑」
- 通用评论文章 → 「资深媒体编辑」

```
你是一个挑剔的资深{领域}编辑，专门负责审稿。你的工作是找出文章中的所有问题，不是夸奖。

已验证的数据源（这些数字来自实时API抓取，不需要质疑准确性）：
{列出文章中引用的所有具体数字及其来源}

审稿标准：
1. 事实准确性：每个数字、对比、引用是否可查证？注意：上面列出的数据源已验证，不要标记为「无出处」。
2. 逻辑漏洞：论点之间的推理链是否完整？有没有跳步？
3. 立场偏颇：是否过度偏向某一方？（注：观点型文章允许有立场，重点看论证是否充分、对立面是否被承认）
4. 论据厚度：每个论点是否有足够的事实支撑？有没有空泛的判断？
5. 读者价值：读完能让读者做出什么决定？还是只是「觉得你说得对」？
6. 风格问题：是否有AI味、套话、禁用词？

⚠️ 区分「观点偏颇」和「论证不足」：观点文章可以立场鲜明，只要论证链完整、对立面被承认即可。不要因为作者有明确立场就标记🔴。
```

输出格式同上（🔴🟡🟢三级）。

## 使用方式

在写作流程中，写完正文后自动触发：

```python
delegate_task(
    goal="审稿：找出文章中的所有问题",
    context=f"""
    文章正文：
    {article_content}
    
    定调：{framing}
    
    质检标准：
    1. 事实准确性
    2. 逻辑漏洞
    3. 立场偏颇
    4. 论据厚度
    5. 读者价值
    6. 风格问题
    
    输出审稿报告，标注🔴🟡🟢三级。
    """
)
```

## 与现有流程的集成

```
writing-draft → [独立质检] → [通过] → publishing-doc
                        ↓ [不通过]
                    writing-draft（修改后重新提交）
```

## 注意事项

- 子agent没有当前对话上下文，必须把所有信息通过context传入
- 子agent的审稿结果只返回摘要，不返回完整对话
- 如果审稿发现🔴问题，应该在发布前修复
- **必须传入数据源清单**：把文章中引用的具体数字及其来源（API名、新闻日期）列出来，否则子agent会把已验证数据标记为「无出处」
- **领域匹配**：根据文章内容选择正确的审查者角色（汽车/科技/消费/通用），不要硬编码
- **立场容忍度**：对观点型/评论型文章，子agent可能过度要求「平衡」。收到报告后需人工判断——用户偏好犀利观点，不要因子agent说「立场偏颇」就削弱论点
