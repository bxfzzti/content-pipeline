# Multi-Agent Prompt Design Principles (2026-06-17, 两次测试验证)

## 核心原则：负面示例 > 正面约束

写prompt时，**正面约束（"必须用XX"）经常被Agent忽略**。Agent倾向于自创格式、评分体系和框架，而不是按规定的来。

**解决方案：每条约束必须加负面示例。**

### 无效（Agent忽略）：
```
评分必须用40分制
```

### 有效（Agent遵守）：
```
评分必须用40分制：时效性×2 + 讨论热度×2 + 情绪强度×2 + 内容关联度×2，满分40分。
**不能自创评分体系（如10分制、5分制、百分制）**。每个维度必须单独打分（1-5分），然后乘以权重2，最后求和。
```

### 无效（Agent自创框架）：
```
框架选择必须用决策树
```

### 有效（Agent遵守）：
```
框架选择必须用决策树。**不能自创框架名称**（如"争议对比型""深入技术解读型"），
必须从5种预设框架（AIDA/PAS/故事弧线/对比结构/递进结构）中选择。
```

## Prompt设计铁律

1. **约束必须加负面示例**：只说"必须用XX"Agent不一定遵守，必须加"不能用XX，如XX"
2. **prompt不能太长**：热点数据Agent 161秒、质检Agent 140秒，部分原因是prompt太长。核心约束应精简，详细内容放references。
3. **Agent会自创框架/维度**：结构Agent会自创"争议对比型"，质检Agent会自创L6——必须在prompt里明确禁止
4. **输出格式必须明确**：必须在prompt里明确是markdown还是JSON
5. **平台风格要求必须单独列出**：写作Agent默认输出偏正式媒体风格，必须单独列出小红书风格要求（口语化、短段落、emoji、互动引导、话题标签）
6. **钩子可以用设问句**：正文不能用设问引导，但钩子可以用设问
7. **质检L6应正式纳入**：不要让Agent自创检查维度，把L6补充检查正式纳入prompt
8. **Agent间信息传递必须标准化**：用message-format.md定义的格式，不能用自然语言

## 验证过的Agent架构（8个Agent）

| Agent | 职责 | 关键约束 | 测试状态 |
|-------|------|---------|---------|
| 主Agent | 纯调度 | 不写、不搜、不发 | 未单独测试 |
| 热点数据Agent | 数据质量评估 | 自动去重、纠正分类、标注情绪强度 | ✅ 通过 |
| 筛选Agent | 选题筛选 | 40分制、切入方向标注类型 | ✅ 通过 |
| 结构Agent | 文章结构 | 决策树选框架、钩子配套 | ✅ 通过 |
| 写作Agent | 搜索事实+写正文 | 事实补充驱动、小红书风格要求 | ✅ 通过 |
| 质检Agent | 文章质检 | web_search验证、L0-L6固定维度 | ✅ 通过 |
| 修复Agent | 按质检报告修复 | 按严重程度排序、标注原文→修改后 | ✅ 通过 |
| 发布Agent | 发布到飞书 | 5方向×2备选标题 | ✅ 通过 |

## 信息传递格式

标准化格式定义在 `references/message-format.md`。关键规则：
- 主Agent按标准格式组装信息后传给子Agent
- 子Agent按标准格式输出，供下一个Agent直接消费
- 信息缺失时子Agent问主Agent，不编造

## 迭代控制

- 质检→修复→重质检：最多3轮
- 停止条件：连续2轮无新增问题

## 完整工作流

```
热点数据 → 热点数据Agent（质量评估）
    → 主Agent组装信息
    → 筛选Agent（选什么、从哪切入）
    → 主Agent确认选题
    → 结构Agent（怎么组织）
    → 主Agent定调
    → 写作Agent（搜索事实+写正文）
    → 质检Agent（写得对不对、好不好）
    → 修复Agent（按质检报告修复）
    → 质检Agent（最终确认，最多3轮）
    → 发布Agent（发布到飞书）
```
