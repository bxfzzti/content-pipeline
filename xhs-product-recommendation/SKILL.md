# XHS 好物种草文创作流水线

选品 → 做功课（评价研究+比价） → 写正文 → 生成配图 → 发布飞书

## 核心原则

用户（@村长不开车）没有实际使用过推荐的产品。创作方法：
1. **做功课**：综合京东/淘宝/SMZDM/小红书上的真实用户评价，提炼高频好评/差评关键词
2. **写法**：用「我用了」口吻写（用户明确接受），但体验细节必须基于真实评价
3. **配图必须有**：HTML渲染产品卡片→浏览器截图，生成9张图（1封面+8单品）

## Step 1: 选品

从以下来源选择8-10个产品：
- 小红书热门博主的推荐（搜索「XX好物推荐」）
- SMZDM什么值得买的好价/好评排行
- 京东/淘宝销量排行+好评率
- 用户所在品类的行业KOL推荐

**选品标准：**
- 具体到品牌+型号（不能是泛品类）
- 京东/淘宝有真实销量和评价
- 价格区间：中等偏上（不过贵也不过便宜）
- 品类分散（不能同一个品牌出现2次以上，否则像软广）

## Step 2: 做功课

对每个产品研究：
1. **好评高频词**（从50-100条评价中提炼）：稳固、好看、方便、耐用...
2. **差评高频词**：发热、容易掉、噪音大、续航短...
3. **价格**：京东/淘宝/拼多多当前价格
4. **竞品对比**：同品类其他产品的优劣

**数据来源：**
- 京东商品评价（用浏览器CDP访问）
- 淘宝商品评价（用浏览器CDP访问）
- SMZDM用户评价（用cookie访问）
- 用户主动提供的小红书链接、截图或导出评价；禁止使用个人小红书 Cookie、CLI、MCP 或 CDP 登录态

## Step 3: 写正文

**标题公式：** 数字+时间背书+品类
- ✅ 「8个车上好物❗️用了半年以上还在用❗️」
- ✅ 「研究了200条评价，这8个车载好物值得买」
- ❌ ~~「我的车上好物分享」~~（太平淡）

**正文结构：**
```
[标题：数字+时间/评价数+品类]

[开头：具体场景人设，如「开车三年，每天通勤40公里」]

① 产品名：品牌型号 💰价格
[对比经历：之前用A有XX问题→换了B解决了]
[具体使用场景和体验]
[缺点：诚实写，但不过度]
🔑 关键词：XX、XX、XX

② ... (重复8-10个)

---
[总价总结+时间锚点]
[互动引导：问句+评论区引导]

[话题标签8-10个]
```

**写作规则：**
- 每个产品必须有缺点（但缺点是「可以接受的小问题」，不是致命伤）
- 对比链路：「之前用A→问题→换了B→解决了」
- 不要同一个品牌出现2次以上
- 价格标注时间锚点（「以下价格是我去年买的时候的价格」）
- 总价要算对（评论区会有人算）
- 避免参数堆砌（IMX678传感器普通人不关心→改成「晚上拍车牌很清楚」）
- 避免套话（「踩过的坑」「少走弯路」最多出现1次）

## Step 4: 生成配图

**配图不能省。** 小红书是图文平台，没有图=白写。

**图片编排（9图格式）：**
1. 封面图：所有产品平铺+标题+总价
2-9. 每个产品一张：产品名+价格+卖点+一句话描述

**生成方式：** HTML渲染→浏览器截图
```bash
python3 ~/.hermes/skills/publishing-doc/scripts/gen_xhs_images.py
```

**后续优化方向：**
- 从电商平台抓真实产品图（替换emoji图标）
- 加入用户评价截图（从京东/淘宝评价区截取）
- 加入价格对比表（淘宝vs京东vs拼多多）

## Step 5: 发布

```bash
# 发布正文到飞书
python3 ~/.hermes/skills/publishing-doc/scripts/publish_to_feishu.py <article.md> "标题"

# 插入配图到飞书文档
python3 ~/.hermes/skills/publishing-doc/scripts/add_images_to_doc.py <doc_id> \
  --after "匹配文本" /tmp/xhs_images/cover.png \
  --after "匹配文本2" /tmp/xhs_images/product_1.png
```

## 独立质检

好物文的质检重点：
1. **品牌集中度**：同一品牌不能出现2次以上
2. **事实错误**：LED数显显示的不是电压是功率、参数不能堆砌
3. **缺点真实性**：缺点不能蜻蜓点水，要有「差点退货」的真实感
4. **套话检查**：「少走弯路」「试错试出来的」最多出现1次
5. **算术检查**：总价必须和实际加总一致

## 已知坑位

1. **倍思三连**：8个产品中倍思出现3次→被读者喷「软广合集」。解法：同一品牌最多1-2个
2. **参数堆砌**：行车记录仪写「索尼IMX678传感器」→普通人不关心。解法：改成体验描述
3. **缺点蜻蜓点水**：每个产品缺点都是「就是XX，看个人接受度」→像象征性吐槽。解法：挑1-2个加重笔墨
4. **配图不能省**：纯文字好物文在小红书没有传播力。必须配图
5. **价格算术**：总价要精确，评论区一定有人算
