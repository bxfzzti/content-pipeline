# angle-selection

选题确认后、定调之前，系统化探索和选择文章切入角度。**只选角度，不定调，不写正文。**

## 为什么需要这一步

同一个选题，切入角度不同，标题方向、读者群体、文章结构完全不同。

例：「中央空调费电」
- 认知颠覆型 → 标题："中央空调费电？你被这句话骗了十年"
- 选购决策型 → 标题："什么情况装中央空调，什么情况装挂机"
- 算账对比型 → 标题："中央空调vs挂机，5年总花费差多少"

**不选角度就定调，等于没想清楚就动笔。**

## 已确认选题的连续性

当用户已经在上一步确认了选题，进入角度选择时必须沿用已确认选题。用户说「好了吗」「继续跑流程」「按你的建议来」这类话，默认不是换题。

只有用户明确说「换成X」「不写刚才那个」「改写Y」时，才切换选题。

输出仍按金字塔原理：先给推荐角度，再给分析过程。

## 理论依据

本Skill的角度分类基于以下框架综合归纳（详见 `references/content-angle-frameworks.md`）：

1. **中文新媒体6大切入角度**（人人都是产品经理、知乎专栏等）— 消费决策类内容的经典切入类型
2. **Nicolas Cole「Content Angle Methodology」**（Write With AI, 2023-2026）— 对同一主题旋转不同角度的系统方法
3. **Wes Kao「Spiky Point of View」**（2020）— 角度质量的5特征检验标准
4. **Eugene Schwartz《Breakthrough Advertising》（1966）** — 读者5个认知阶段，决定角度匹配

## 第零步：KOL微博观点采集（选题确认后、角度生成前）

**选题确认后，第一时间运行 weibo-topic-signal 抓取相关KOL的48-72小时发言。**

**同时，检查角度库是否有历史相似角度：**

```bash
/tmp/zvec-poc/bin/python /Users/xxqq/.hermes/zvec-content-poc.py search_angles "<选题关键词>" 5
```

**判断标准**：
- 返回空 → 没有历史角度，正常生成
- 返回结果且 score ≥ 0.80 → 有高度相似的历史角度，直接复用或在其基础上迭代
- 返回结果且 0.65 ≤ score < 0.80 → 有相关历史角度，作为参考避免重复

**角度库结果必须写入输出**：在角度分析中加上"历史角度参考"字段。

**注意**：zvec 知识库的完整 API 文档见 article-pipeline skill 的 `references/zvec-integration.md`。

这些发言不是热点来源（热点已在Step 1抓到），而是**角度参考**——看看行业里有影响力的人怎么看待这个话题，他们的表达方式、争议点、反面观点，都可以成为我们选角度的素材。

```bash
weibo-topic-signal --source ajax --context "<选题关键词>" --max-items 10
```

**24个监控账号：**
奶爸兄地、一苒、不是郑小康、电动兄弟、孙少军09、理想TOP2、花叔、Navis-慢点评测、韩路、柳笛、南哥说车、kang、李楠或kkk、张抗抗KK、麦子俊i、新出行贺磊、JackyQ_Talking、董买买、陈抱一、理记、科技新一、番茄殿下

**采集后做什么：**
1. 提取每个KOL的核心观点（支持/反对/中立？有什么独特的判断？）
2. 标注哪些观点跟我们的候选角度重叠（重叠=验证，不重叠=可能是独特角度）
3. 记录KOL的表达方式（有没有特别好的比喻、金句、反问可以参考？）
4. 如果KOL的观点跟我们的角度完全一致→考虑换一个不同的角度

**失败处理：** weibo-topic-signal 超时或返回空→跳过，不阻塞主流程。

## 第一步：生成候选角度

**用3个独立子agent分别从不同轴（痛点/误解/方法）提出角度建议，然后汇总讨论。**

**完整的角度选择Agent prompt**：`references/angle-agents.md`

**执行方式：**
```python
delegate_task(tasks=[
    {"goal": "痛点轴角度", "context": "选题信息+角度Agent prompt（从references/angle-agents.md读取）"},
    {"goal": "误解轴角度", "context": "选题信息+角度Agent prompt（从references/angle-agents.md读取）"},
    {"goal": "方法轴角度", "context": "选题信息+角度Agent prompt（从references/angle-agents.md读取）"}
])
```

**结果汇总速查**：3个agent角度重叠→优先考虑；角度完全不同→可组合。用户自带角度作为第一候选。SPOV≥14分的角度重点考虑。

### 8种切入类型

| 类型 | 核心逻辑 | 适合的选题特征 |
|------|---------|-------------|
| **① 认知颠覆型** | 打破"你以为的"，制造认知冲突 | 有普遍误解/过时认知的选题 |
| **② 选购决策型** | 帮读者做A还是B的决定 | 有明确对比对象的选题 |
| **③ 问题解决型** | 从读者痛点出发，给解决方案 | 有明确痛点的选题 |
| **④ 算账对比型** | 用数字/成本说话 | 可量化比较的选题 |
| **⑤ 体验种草型** | 讲真实使用感受，制造向往 | 有产品/体验可讲的选题 |
| **⑥ 避坑排雷型** | 帮读者规避风险和陷阱 | 有常见踩坑点的选题 |
| **⑦ 趋势洞察型** | 从行业/市场变化切入 | 有更大趋势可关联的选题 |
| **⑧ 观点输出型** | 一个明确判断，不怕争议 | 有争议空间的选题 |

### 生成方法：Nicolas Cole 三轴旋转法

对同一个选题，从三个轴各转一次，找到不同切入：

- **痛点轴：** 这个选题里，读者最痛的具体问题是什么？
- **误解轴：** 这个选题里，大家普遍搞错的是什么？
- **方法轴：** 这个选题里，我能给一个什么可复用的方法/框架？

每个轴转出的角度，对应上面8种类型中的1-2种。

### 匹配读者认知阶段

选角度时，同时考虑读者当前处于什么阶段（Schwartz 5阶段）：

| 读者阶段 | 最佳切入类型 |
|---------|------------|
| 不知道自己有问题 | 认知颠覆型、趋势洞察型 |
| 知道有问题，不知怎么办 | 问题解决型、避坑排雷型 |
| 知道方案，不知选哪个 | 选购决策型、算账对比型 |
| 已选好，需要确认 | 体验种草型、观点输出型 |

**操作：** 先判断这个选题的典型读者处于什么阶段，再从对应的切入类型中选。

## 第二步：生成角度卡片

每个候选角度输出一张卡片：

```
**[类型名] — [一句话描述这个角度要说什么]**

- 标题方向：[标题会往哪个方向走，给1-2个标题示例]
- 定调方向：[framing会往哪个方向走]
- 适用场景：[什么情况下选这个角度最合适]
```

## 第三步：SPOV 质量检验

用 Wes Kao 的 Spiky Point of View 5特征，对每个候选角度打分（1-3分）：

| 特征 | 检验问题 | 1分 | 3分 |
|------|---------|-----|-----|
| **可争论** | 别人能不同意吗？ | 所有人都会同意 | 粉丝会想反驳 |
| **有立场** | 有没有明确判断？ | 两边都说好 | 旗帜鲜明 |
| **有具体性** | 是不是针对具体场景？ | 泛泛而谈 | 指名道姓 |
| **有依据** | 有没有事实/数据支撑？ | 纯喊口号 | 有具体案例 |
| **读者在乎** | 读者真的关心吗？ | 自嗨 | 直击痛点 |

**评分标准：**
- 12-15分 → S级，强烈推荐
- 9-11分 → A级，可以写
- 6-8分 → B级，需要打磨
- ≤5分 → 放弃，换角度

**犀利度检查：** 把角度读出来，问自己——这个判断会不会让某一方不舒服？如果所有人都觉得"说得对"，那大概率是正确的废话。

## ⚠️ 标题是角度的核心浓缩（2026-06-15 教训）

小红书是图文平台，**标题就是角度的浓缩表达**。标题不是写完正文再想的，是在选角度时就要确定方向的。

**核心关系：先定角度 → 再定标题结构 → 最后填充关键词**

同一内容，角度不同标题完全不同：
- 测评角度 → 「XX深度测评30天，这几个缺点忍不了」
- 避雷角度 → 「买XX前你必须知道的5件事」
- 反差角度 → 「开了8年车才知道，原来XX一直都错了」

**标题核心原则（小红书图文逻辑）：**
- 最佳字数：18-25字（超25字信息流截断）
- 核心关键词放标题前10字（信息流只展示前两行）
- 搜索关键词必须出现在标题中（SEO优先）

**5类情绪触发词：**
- 好奇型：原来、竟然、真相、秘密、冷知识
- 紧迫型：赶紧、马上、必须、千万别、最后X天
- 认同型：真的绝了、太好用了、后悔没早知道
- 反差型：以为XX结果XX、没想到、翻车
- 从众型：全网都在买、人手一个、断货王

**5个结构化标题公式：**
1. 数字+痛点+解决方案 → 「3个方法解决XX问题」
2. 身份+场景+结果 → 「上班族通勤30天，这台车太香了」
3. 否定+重塑认知 → 「别再XX了！正确做法是XX」
4. 悬念+未完成感 → 「看到最后我沉默了…」
5. 对比+结论 → 「XX vs XX，差距太大了」

**⚠️ 选角度时就要同时想好标题方向，不能等写完正文再补标题。**

## ⚠️ 用户自带角度怎么办（2026-06-06 实测）

用户经常带着一个已经成型的角度来跑流水线（如「我觉得理想搞错了重点，应该讲5C增程」）。这时**不要从零开始分析**，而是：

1. **把用户的角度作为第一候选**，直接进入 SPOV 评分
2. **用三轴旋转法补充 2-3 个其他候选角度**，作为对比参照
3. 如果用户的 SPOV 评分 ≥12/15 → 直接推荐，不做无意义的"选择"
4. 如果 SPOV < 12 → 指出哪里弱，建议调整或换角度

**实测案例：** 用户说「理想更应该宣传5C增程而不是跟蔚来比底盘」，SPOV 得 15/15，直接推荐，同时补充了「问题解决型」和「趋势洞察型」作为对比候选。用户确认后进入定调。

**本质：** 角度选择不是为了推翻用户已有的好判断，是为了验证和补充。

## 边界

**不做：** 定调、取标题、写正文、规划论点结构。完成角度选择后等待用户指令：
- 「就这个角度」→ 调用 `framing-article`（用推荐角度作为输入）
- 「换一个」→ 重新分析其他候选角度
- 「这个角度再想想」→ 用不同的三轴旋转重新生成
- 「直接定调」→ 跳过确认，直接调用 `framing-article`

## ⚠️ 犀利角度方法论（2026-06-10 实测）

用户多次反馈「这些方向都不行 不够犀利」。根本原因：给的角度是「行业分析师」视角（市场格局、竞争态势、产品对比分析），而不是「有态度的观察者」视角。

**犀利角度的4个来源：**

1. **事实矛盾反差** — 两个事实放在一起产生的冲突感
   - 例：「大疆在法庭上告影石，在市场上被影石牵着走」
   - 方法：搜到两个矛盾的事实，把它们并排放

2. **竞争对手的隐藏意图** — 表面行为背后的真实动机
   - 例：「大疆故意等影石出牌再发布4P，霸主玩后手说明什么？」
   - 方法：搜索时间线、爆料、行业传闻，找到「巧合」背后的逻辑

3. **行业历史类比** — 把当前事件放到历史坐标里
   - 例：「大疆现在像不像2015年的GoPro？」
   - 方法：搜索行业历史，找到结构性相似的先例

4. **反直觉结论** — 看似强的其实弱，看似弱的其实强
   - 例：「不是影石太强，是大疆太舒服了」
   - 方法：问「这件事的反面是什么？」然后论证反面

**角度命名规则：**
- 必须是判断句，不是描述句
- ❌ 「影石Luna Ultra vs 大疆Pocket 4P对比分析」
- ✅ 「大疆在法庭上告影石，在市场上被影石牵着走」
- 一句话就要有冲突感，让读者产生「怎么说？」的好奇

**给角度时的自检：**
- 这个角度是分析师能写的，还是只有有态度的观察者能写的？
- 读出标题，问自己：这句话会不会让某一方不舒服？
- 如果所有人都觉得「说得对」，那大概率是正确的废话，换一个

**禁止给的角度类型：**
- ❌ 「市场格局分析」「行业趋势洞察」「产品对比评测」— 这是分析师视角
- ❌ 「XX vs XX，谁更值得买」— 这是选购决策型，不够犀利
- ✅ 要给「有立场、有判断、有冲突感」的角度

## ⚠️ 备选标题必须多给（2026-06-10 教训）

用户明确要求文章末尾附多个备选标题，按类型分组。标准：至少15-20个，分5类（反差型、人物型、判断型、口语化/情绪型、金句型）。标题要覆盖不同切入点，让用户自己挑。

**标题分类框架：**
- 反差型：前后对比、预期反转
- 人物型：聚焦创始人/关键人物
- 判断型：明确立场、可量化的结论
- 口语化/情绪型：像说话、有情绪
- 金句型：一句话能记住的

## 实战教训（2026-06-06 首次跑通）

**角度选择的价值在于"组合"：** 用户给的选题信息往往包含多个潜在角度（如"理想PR翻车"和"理想应该讲5C增程"）。角度选择的作用不是二选一，而是把它们组合成一个更有穿透力的判断（"理想搞错了战场"）。

**用户已有强烈倾向时，角度选择仍然有价值：** 用户明确说了"理想搞错了重点"，但角度选择帮他把这个判断结构化了——认知颠覆型+观点输出型的组合，配合SPOV评分，让定调更扎实。

**角度选择直接影响标题方向：** 选了"认知颠覆型"，标题就往"搞错了战场"方向走；选了"观点输出型"，标题就往"应该讲5C增程"方向走。角度没定，标题也取不好。
