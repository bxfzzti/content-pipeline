# 小红书内容线总契约

## 账号定位

账号不是单纯的汽车博主，也不是纯干货教程号。

核心定位是：

> 一个有行业判断力的消费者，带用户用内部视角做消费决策。

所以内容流的总目标不是“把热点写完”，而是把外部素材转化成三种账号资产：

- 热点观点线：用热点做入口，换取流量、评论、转发和涨粉。
- 消费决策线：用产品和场景解决选择困难，换取收藏、搜索、信任和私信咨询。
- 长期框架线：把一次判断沉淀成可复用方法，换取账号心智、系列资产和长期搜索。

三条线不是品类分类。汽车、3C、智能家居、AI 工具都可以进入任意一条线。分流依据只有一个：这篇内容承诺给读者什么。

## 从素材到内容线

素材进入后，先判断它是哪类外部事实，再判断它能给读者什么。

### 1. 外部事实类型

- 公共热点：热搜、榜单、政策、品牌回应、财报、发布会、事故、争议。
- 产品事件：新品发布、上市、预售、降价、配置变化、交付、体验、横评。
- 体验材料：什么值得买、少数派、Chiphell 等公开内容里的开箱、吐槽、评测、踩坑。
- 方法材料：一个反复出现的问题，例如“增程和纯电怎么选”“扫地机到底看什么”“发布会话术怎么翻译”。

外部事实类型只决定候选优先级和证据要求，不直接决定内容线。

### 2. 内容线分流问题

按以下问题做三选一：

- 读者最想知道“这件事我该怎么看”吗？进入 `hot_take`。
- 读者最想知道“我该不该买、该等还是该避、怎么选”吗？进入 `decision`。
- 读者最想得到“一套以后还能复用的判断方法”吗？进入 `framework`。

如果一个选题三条线都能写，按当天目的选择：

- 要抢时效和评论：选 `hot_take`。
- 要建立信任和收藏：选 `decision`。
- 要沉淀账号资产：选 `framework`。

不要把“能抽象出一点道理”误判为 `framework`。`framework` 必须能产出可命名、可步骤化、可复用的判断工具；如果只是一个正在发生的新事实、公司经营反差或公共争议，默认仍优先归 `hot_take`。如果只是一个具体产品选择，默认仍优先归 `decision`。

## 三条线的判定标准

### 热点观点线 `hot_take`

读者承诺：我帮你判断这件事到底说明了什么。

适合素材：

- 新事实强，大家已经知道事件，但还没形成共识。
- 有公共情绪、站队、反差、品牌战争或行业冲突。
- 结论可以写成一句锋利判断，而不是资讯复述。

不适合素材：

- 只是参数更新、单品体验、弱信息流。
- 没有争议，或者一句话就能说完。

进入下一步前必须补：

- 事件时间和原始来源。
- 至少两个相反立场或评论区分歧。
- 一个可证成的核心判断。

常用结构：

- 事实反差 -> 行业判断 -> 普通人结论。
- 反常识 -> 拆解 -> 重新定义。

### 消费决策线 `decision`

读者承诺：我帮你做一个更少后悔的选择。

适合素材：

- 车型、手机、家电、AI 工具等具体产品。
- 新品发布、预售、降价、配置变化、真实体验、横评、吐槽。
- 读者存在明确选择成本，例如买不买、等不等、A 和 B 怎么选。

汽车属于高客单价消费品，默认要优先评估消费决策价值。不能因为来源是汽车媒体，就自动归入热点观点线。

不适合素材：

- 只有公司财报、融资、行业战略，暂时无法落到具体消费者选择。
- 产品信息太少，无法形成行动建议。

进入下一步前必须补：

- 价格、配置、场景、人群边界。
- 竞品或替代方案。
- 明确结论：谁该买、谁不该买、谁应该等。

常用结构：

- 问题 -> 对比 -> 决策。
- 参数 -> 场景 -> 值不值。
- 踩坑 -> 反思 -> 推荐。

### 长期框架线 `framework`

读者承诺：我给你一套以后还能反复使用的判断工具。

适合素材：

- 一个问题会反复出现，而不是只属于今天。
- 能抽象成步骤、清单、四象限、五问、话术翻译器或选择模型。
- 可以跨品牌、跨产品、跨时间复用。

硬门槛：

- 必须能命名一个方法，例如“买车五问”“发布会话术翻译器”“扫地机避坑四象限”。
- 必须能写出至少 3 个判断步骤。
- 必须能用 1 个以上案例演示，而不是只对当天事件发表感想。

不适合素材：

- 只有短时情绪，没有可迁移规律。
- 只适用于单个产品，无法抽象成方法。
- 只有“行业趋势值得长期观察”，但写不出具体步骤。

进入下一步前必须补：

- 框架名称。
- 判断步骤。
- 至少一个热点或产品案例演示。

常用结构：

- 概念定义 -> 判断步骤 -> 示例演示。
- 误区清单 -> 框架重建 -> 使用场景。

## 打分边界

当前正式筛选总分是统一五维 50 分，不是三条线各自单独算总分。

代码负责前三项：

- 全网热度 `heat_score`：平台数、榜单位置、传播广度。
- 时效性 `freshness_score`：0-24 小时最高，24-48 小时正常，超过 48 小时默认转储备或淘汰。
- 讨论热度 `discussion_score`：跨平台讨论数量和集中度。

模型负责后两项：

- 情绪强度 `emotion_score`：是否有争议、站队、反差、评论冲突。
- 内容关联度 `relevance_score`：是否匹配账号定位，能否产出观点、决策或框架。

总分公式：

```text
writing_value_score = (heat + freshness + discussion + emotion + relevance) * 2
```

等级：

- 40-50：S 级，优先写。
- 30-39：A 级，值得写。
- 20-29：B 级/储备。
- 低于 20：不推荐。

正式推荐还必须满足：

- `writing_value_score >= 30`
- `relevance_score >= 3`
- `recommended_angle` 不能是“不适用”
- 同一品牌最多 2 条
- 汽车默认不超过最终推荐列表的一半

内容线本身不加分、不扣分。它决定后续生产方式，不替代总分。

## 从内容线到生产流程

### `hot_take`

下一步重点：

- 角度选择：先找反差、冲突、历史类比或隐藏意图。
- 定调结构：核心论点必须是判断句。
- 写作要求：先亮结论，再用事实支撑，结尾落到普通人的理解。

产物检查：

- 标题是否直接表达判断。
- 开头是否不是新闻复述。
- 是否有至少一个反面立场。

### `decision`

下一步重点：

- 角度选择：把话题改写成真实购买困惑。
- 定调结构：必须选择消费决策框架。
- 写作要求：参数服务场景，结尾给人群边界。

产物检查：

- 是否明确“谁该买/谁不该买/谁该等”。
- 是否有竞品或替代方案。
- 是否能被收藏后照着用。

### `framework`

下一步重点：

- 角度选择：把单次事件抽象成反复出现的问题。
- 定调结构：必须命名一个判断模型。
- 写作要求：先讲方法，再用案例演示。

产物检查：

- 是否有清晰步骤。
- 是否能跨品牌/产品复用。
- 是否适合做系列封面或长期合集。

## 协同方式

主 Agent 负责贯穿全流程，不把每一段拆成互不相干的 Agent。

- 热点抓取：只收集素材，不做最终价值判断。
- 候选准备：代码做时效、去重、热度、品类配比和默认分流提示。
- 模型筛选：模型只做语义判断、内容线、情绪、关联度、角度和风险。
- 代码终审：代码统一复算总分、排序、品牌限制和数量限制。
- 角度/定调/写作：继承 `content_line`，按对应内容线选择模板。
- 质检：检查事实、结构、读者收益和平台表达。

如果用户没有明确要求全自动，必须在这些节点停下来确认：

- 选题筛选后。
- 角度选择后。
- 定调结构后。
- 发布前质检后。
