# screening-topics

接收原始热点列表 → 跑五问选题审查 + 传播势能判断 → 输出选题建议。**只出建议，不写正文。**

## 输出纪律（本用户）

按金字塔原理输出：**先给最终排序结论，再给理由**。用户要的是「有什么值得写」时，不要先展示完整热点清单、工具过程或长篇分析。

推荐格式：

```
结论：今天优先写 A，其次是 B。

1. A — S级 — 为什么值得写 — 2-3个标题
2. B — A级 — 为什么值得写 — 2-3个标题
3. C — B级/储备 — 为什么暂缓
```

用户说「跑流程」「一条龙」「跑一次流程」时，**选完题直接进入下一步，不要反复问用户选哪个**。自己判断最佳选题，直接进角度选择→定调→写作。用户要的是看完整流程跑通的结果，不是在中间节点反复做选择题。

用户说「你问我的这些问题 是你应该搜索得到的 而不是问我」——所有信息都先搜索，不要问用户。选题判断、角度选择、数据核实全部自行完成。

**标题要多取（15-20个），分5类**（反差型/人物型/判断型/口语化/金句型）。用户会说「只能取这么些吗」——给少了比不给更差。

**⚠️ 关键教训（2026-06-11）：** 用户说「你没有给我发选题」——原因是选题建议夹在大量工具输出中间，被淹没了。**选题结论必须作为独立消息块发给用户**，不能紧跟在工具调用输出后面。如果前面有长段工具输出，先换行/分隔，再发选题。

**⚠️ 语义判断 vs 关键词匹配（2026-05-30 实测）：** 五问审查不能用纯关键词匹配实现。例如：
- "一小时大定11000台"隐含消费决策信号，但标题没写"怎么选/值不值" → 关键词会漏
- "问界M9"当然关联行业趋势，但标题没写"趋势/格局" → 关键词会漏
- 正确做法：关键词做粗筛（快速排除无关条目），语义判断做细筛（用LLM评估"这个标题背后的事件能不能写出好文章"）。两种方式结合，不要只用一种。

**⚠️ 品类分流误分类（2026-06-01 实测）：** 关键词过滤存在跨品类误分类：
- **家居"品牌"误命中：** 小米既是汽车/3C品牌也是家居品牌，纯"小米"命中会被归入家居。修法：小米必须有家居上下文(扫地/洗地/门锁/智能家居)才归家居，否则归3C或汽车。
- **家居"上下文"过度匹配：** "家居上下文"正则过宽（家电/家居/厨卫/卫浴/清洁），导致"尼克尔镜头开发者访谈"误命中（文中出现"清洁"描述镜头镀膜工艺）。修法：家居上下文关键词需与家居品类词同时命中才归类。
- **高频人名误入家居：** "雷军回应武契奇""卢伟冰谈涨价"等含"小米"的新闻被归入家居，实际是汽车/3C新闻。修法：人物词(雷军/卢伟冰等)命中时默认归汽车或3C，除非有明确家居品类词。
- **AI品类仍偏大（808条）：** 英伟达/AMD/Intel/芯片等关键词命中大量普通半导体新闻，与AI大模型无关。修法：AI品类的"芯片/算力/GPU"需搭配AI品牌词(Claude/OpenAI/DeepSeek等)才归类，纯硬件新闻归3C。

**⚠️ AI品类过滤天花板实测（2026-06-03）：** hot-aggregator 3043条 → 初筛AI=496条（品牌命中太宽）→ 收紧为品牌+事件双命中后AI=32条。关键修法：AI品类必须同时命中品牌词(Claude/OpenAI/DeepSeek/GPT/豆包/宇树/英伟达)和事件词(发布/合作/战略/IPO/融资/收费/上线)。纯品牌无事件的条目（如"OpenAI的XX论文"）不归AI品类。实测效果：496→32条，准确率大幅提升。

关键坑位：
- 必须基于实际抓到的热点数据筛选；没抓到数据时不能假定「没有值得写」。
- **数据时效性检查：** 使用热点数据前，先检查数据文件的时间戳。超过24小时的数据标记为「待刷新」，超过48小时的数据不直接使用——先用浏览器搜索当天最新热点补充。2026-06-06实测：hot-aggregator数据是6月4日的（48小时+），直接用会漏掉当天新热点（如英伟达市值蒸发2.2万亿、理想L8月底发布等）。
- 过滤领域关键词时要避免把无关词误判为汽车选题，例如普通句子里的「车」可能只是交通/成语/上下文噪声。优先看汽车品牌词、事件词和行业语境。
- 一旦用户确认主选题，后续流程默认延续该选题，除非用户明确说「换成另一个」。
- **配比可偏离：** AI品类在重大事件日（如Computex、WWDC、GTC）可能远超15%目标——这是事件驱动的正常偏离，不必强行压缩。家居品类在无新品发布日常常为0%——接受为储备品类。配比检查的作用是提醒而非强制。

## 第二步：五问选题审查

每条候选话题逐一跑五问：

```
Q1 事实层够不够？
  标准：≥3 个独立可查证的事实点（具体人/事/数字/时间）
  操作：搜索时顺手记事实点数量，少于3个 → 降级或放弃

Q2 有没有争议空间？
  标准：至少2种不同立场且都有受众
  操作：同时搜"支持方"和"反对方"，只有一方自嗨 → 降级

Q3 能不能关联更大趋势？
  标准：能从"这件事"推导出"这类事的走向"，至少1层
  操作：问"背后什么在变？"答不上 → 降级

Q4 我有没有别人没有的角度？
  标准：至少1个别人不会说的核心判断
  操作：写不出"别人没说过的"就不写

Q5 读完能让人做一个决定吗？
  标准：读者能得出具体 action（买/不买/等/换/重新理解）
  操作：想象不出读者看完做什么 → 降级
```

**⚠️ Q6 认知起点预判（新增，来自得到品控手册）：**

在五问通过后，S级和A级选题必须补充认知起点预判——读者看到这个话题时，"最顺理成章的反应"是什么？

```
Q6 读者的认知起点是什么？
  标准：能用一句话描述读者的现有认知/偏见/误解
  操作：写出"大多数人看到这个话题会觉得XXX"
  价值：这个认知起点直接传递给 framing-article，作为开篇切入的依据
  示例：
    - 话题：理想5C增程发布 → 认知起点："增程是过渡方案，迟早被淘汰"
    - 话题：小米SU7 Ultra圈速 → 认知起点："小米是性价比品牌，做不了高端性能车"
    - 话题：比亚迪出海欧洲 → 认知起点："国产车出海靠便宜"
```

**如果写不出认知起点 → 说明这个话题没有认知增量空间，降为B级。**

**决策：**
- 5/5 → S级，立即写
- 4/5 → A级，可写但控制篇幅
- 3/5 → B级，500-800字短评
- ≤2/5 → 放弃

## 第三步：传播势能判断

**高势能（立即写）：**
- 跨平台：3个以上平台同时出现 → 立即写
- 评论情绪：热评前3情绪强烈 → 写
- 窗口期：KOL已发言但评论区未形成共识 → 写
- 话题集群：可与近期热点串联 → 写

**低势能（不追）：**
- 单一平台热搜 → 不单独写
- 峰值超24小时 → 不追
- 评论水军比例高 → 不追
- 事件一句话能说完 → 不写

**时间窗口：** S级热点 6-48h 内最佳，超过48h降级

**呈现规则：** 选题结论必须作为独立消息块发给用户，不能紧跟在工具调用输出后面。如果前面有长段工具输出，先换行/分隔线，再发选题。用户反馈过"你没有给我发选题"——原因是选题被淹没在工具输出噪音中。

**⚠️ 用户自带选题/标题时跳过筛选（2026-06-18 教训）：**
用户说「写XXX」「主题 XXX」「这个话题值得写」时，不要跑五问审查和多agent评估，直接进入 angle-selection 或 framing-article。筛选Agent的价值是"从一堆热点里挑出值得写的"——用户已经挑好了，再筛一遍是浪费时间。

**⚠️ 赛道 ≠ 选题（2026-06-25 教训）：**
"AI+小红书变现""小红书变现""新能源汽车"这些是**赛道/方向**，不是具体选题。具体选题是"苹果涨价20%不是关税的锅""零跑D99今晚发布"这样有明确事件、可写成一篇文章的话题。用户说"ai和小红书 这个不是选题 不要管他"——不要把宽泛方向当作已确认选题跳过筛选。

**⚠️ 赛道≠选题（2026-06-25 教训）：**
用户说「小红书变现是不错的赛道」「AI+小红书方向挺好」时，这是在聊**赛道/领域**，不是在定**选题**。赛道是内容方向（如"汽车评测"），选题是具体可写的话题（如"零跑D99今晚发布"）。**赛道不能跳过热点筛选**——流程仍从 sourcing-hotspots 开始，在 screening 阶段结合赛道方向筛选热点。

```
Step 1: 用户说「这是热点：XXX」
Step 2: 自动出3-5个不同角度的选题方向
Step 3: 每个方向写一篇（delegate_task并行）
Step 4: 同时发布到飞书
Step 5: 观察哪个方向效果好，下次复制该方向的10个版本
```

### 选题方向设计原则
每个方向必须**完全不同**，不是微调。角度必须犀利——有冲突感、有判断、有立场，不能是分析师式的中性描述。

犀利角度的4个来源（详见 `angle-selection` skill）：
- **事实矛盾反差**：两个事实放一起产生冲突
- **竞争对手隐藏意图**：表面行为背后的真实动机
- **行业历史类比**：当前事件的历史坐标
- **反直觉结论**：看似强的其实弱，反之亦然

角度命名必须是判断句不是描述句。❌「XX vs XX对比」 ✅「XX在法庭上告XX，在市场上被XX牵着走」
- 方向A：认知颠覆型（打破普遍误解）
- 方向B：观点输出型（鲜明立场，有争议）
- 方向C：趋势洞察型（关联更大趋势）
- 方向D：选购决策型（帮读者做决定）
- 方向E：体验种草型（真实感受，制造向往）

### 执行方式
用户确认后，用delegate_task并行写作：
```python
delegate_task(tasks=[
    {"goal": "写方向A的文章", "context": "角度+定调+素材"},
    {"goal": "写方向B的文章", "context": "角度+定调+素材"},
    {"goal": "写方向C的文章", "context": "角度+定调+素材"},
])
```

### 效果追踪
发布后观察：
- 哪个方向的阅读量最高？
- 哪个方向的互动（点赞/收藏/评论）最多？
- 哪个方向的转发最多？

**下次热点来临时，优先复制效果最好的方向。**
