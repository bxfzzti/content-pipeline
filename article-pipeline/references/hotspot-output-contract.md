# 热点阶段统一输出契约

本文件是热点抓取、数据质量整理、选题筛选三个阶段共同遵守的唯一契约。其他文件不得复制一套不同顺序的模板。

## 固定顺序

1. **全网热点**：先展示，按分类列出当天值得关注的热点。
2. **我关注的方向**：后展示，只包含汽车媒体、3C 数码、智能家居。
3. **选题建议**：只有前两部分完整整理并通过校验后，才进入评分。

确认点必须生成一份原子结果，固定包含“全网热点 → 我关注的方向 → 选题建议”。不得把前两部分作为中间消息发出后只保留评分结果，不得让选题评分替代热点全景。

## 全网热点分类

- 社会/民生
- 国际/政治
- 财经/政策
- 体育
- 文娱
- 健康
- 科技/AI
- 其他爆点

全网热点不限用户内容方向。汽车、3C、智能家居话题也可以同时出现在全网热点中，但必须以全网热度为入选依据。

## 我关注的方向

- 汽车媒体
- 3C 数码
- 智能家居

AI 不再作为第四个固定关注栏目。高热度 AI 话题进入“全网热点/科技与 AI”；与手机、电脑、硬件产品直接相关的内容可以同时进入 3C 数码。

## 用户可见格式

- 使用标题和项目符号，不使用 Markdown 表格。
- 每条至少包含：标题、热度依据、来源平台数、原文链接或可追溯来源。
- 数据来自缓存时必须标记缓存时间；来源不可用时在末尾汇总，不用工具过程刷屏。
- 热点较多时允许同一张卡片内分组折叠，不得把不同分片混成普通消息和富卡片。

## 阶段产物

- `/tmp/article-pipeline/01-hotspots-presentation.json`：机器可校验的两层热点数据。
- `/tmp/article-pipeline/01-hotspots-presentation.md`：面向用户的两层热点清单。
- `/tmp/article-pipeline/02-topic-suggestion.md`：完成两层热点展示后生成的选题评分。
- `/tmp/article-pipeline/03-hotspot-confirmation.md`：确认点唯一允许发送的合并结果。

进入选题筛选前必须确认：

1. `full_web` 和 `focus` 两个对象都存在。
2. `full_web` 至少包含两个非空分类。
3. `focus` 固定包含 `auto`、`3c`、`smart_home` 三个键。
4. 用户可见 Markdown 中“全网热点”出现在“我关注的方向”之前。
5. 筛选结束后 `02-topic-suggestion.md` 存在且非空。
