# screening-topics 坑位记录

## 输出纪律

- **选题结论必须作为独立消息块发给用户**（2026-06-11）：不能紧跟在工具调用输出后面。用户反馈过"你没有给我发选题"——原因是选题被淹没在工具输出噪音中。
- **先给最终排序结论，再给理由**：金字塔原理。用户要的是「有什么值得写」时不要先展示完整热点清单。

## 语义判断 vs 关键词匹配

六问审查（早期文档称“五问审查”）不能用纯关键词匹配（2026-05-30 实测）。关键词做粗筛，语义判断做细筛——用 LLM 评估"这个标题背后的事件能不能写出好文章"。

## 品类分流误分类（2026-06-01）

- 小米跨品类：需家居上下文才归家居，否则归 3C 或汽车
- 人物词（雷军/卢伟冰）默认归汽车或 3C
- AI 品类偏大：芯片/算力/GPU 需搭配 AI 品牌词
- AI 品类必须品牌+事件双命中（2026-06-03），纯品牌无事件不归 AI（496→32 条）

## 时效性

48-72 小时的数据需要降权并补搜当天最新进展；超过 72 小时默认不追，除非有持续发酵证据。

## 赛道 ≠ 选题（2026-06-25）

"AI+小红书变现""新能源汽车"是赛道/方向，不是具体选题。不要跳过热点筛选。

## 用户自带选题

用户说「写 XXX」时跳过六问审查和多 agent 评估，直接进入 angle-selection 或 framing-article（2026-06-18）。筛选 Agent 的价值是"从一堆热点里挑"，用户已挑好则不再筛。

## 数据流

```
【消费】原始热点列表（来自 sourcing-hotspots 或用户直接提供）
【产出】选题建议（S/A/B 级 + 切入角度）
【本地】/tmp/article-pipeline/02-topic-suggestion.md
【转发】→ framing-article（用户确认选题后）
```
