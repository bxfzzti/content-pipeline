# 两分钟全覆盖热点创作流设计

## 目标

把内容创作流的热点阶段收敛为可预测的两分钟任务，并恢复用户对选题、角度和定调的控制权。

成功标准：

1. 从收到“跑一次内容创作流”开始，120 秒内返回完整热点候选和来源状态。
2. 所有已配置热点来源都必须参与本轮抓取或缓存回退，不能静默遗漏。
3. 小红书个人登录态工具不得被内容创作流调用。
4. 默认在选题、角度、定调三个节点等待用户确认。
5. 同一批产品体验数据只抓取一次，并复用于本地产物和飞书 Base 增补。

## 全量定义

“全量热点数据”指所有已启用来源都进入本轮来源清单，并产生明确状态，不等于所有上游平台都能实时成功返回。

每个来源只能处于以下状态之一：

- `live`：本轮实时抓取成功。
- `cache`：本轮实时抓取失败或超时，使用该来源最近一次有效缓存。
- `unavailable`：本轮实时失败，且没有可用缓存。
- `disabled`：因安全规则或人工配置明确禁用。

最终结果必须附来源统计，至少包含来源总数、实时数、缓存数、不可用数和禁用数。禁止把缓存数据标成实时数据，也禁止把搜索结果包装成热榜。

## 两分钟时间预算

### 0 至 5 秒：准备

- 读取来源清单和最近有效缓存元数据。
- 健康检查本地 `hot-aggregator` 和 `daily-hot-mcp`。
- 不再每次无条件杀进程重启；仅在服务不可用或缓存健康检查失败时重启。

### 5 至 100 秒：并行抓取

以下任务同时启动：

- 国内热点聚合源。
- 国际科技与家居 RSS。
- 什么值得买产品体验关键词池。
- 其他无需个人登录态的公开来源。

每个来源独立设置连接超时和总超时。单源失败不能取消其他来源。实时成功后立即更新该来源缓存；失败时立即读取最近一次有效缓存。

### 100 至 115 秒：统一处理

- 时间窗口过滤。
- URL、标题和事件级去重。
- 跨平台事件聚合。
- 热度、时效、讨论、情绪和内容关联度评分。
- 产品体验稳定分计算。

### 115 至 120 秒：生成首轮交付

- 输出全网热点和关注领域热点。
- 输出产品体验候选。
- 每条候选保留标题、来源、时间、原文链接、评分依据和反面理由。
- 输出来源状态摘要。
- 到达 120 秒必须结束热点阶段，不得因尾部来源继续阻塞。

## 抓取与缓存架构

新增一个热点运行编排层，负责：

1. 维护来源注册表。
2. 并行执行来源适配器。
3. 为每个来源保存独立缓存和更新时间。
4. 在全局截止时间前合并实时结果与缓存结果。
5. 生成机器可读运行清单，记录来源状态、耗时、错误和数据条数。

建议产物：

- `/tmp/article-pipeline/00-source-manifest.json`
- `/tmp/article-pipeline/01-hotspots-raw.json`
- `/tmp/article-pipeline/01-hotspots-raw.md`
- `/tmp/article-pipeline/01b-product-experience.json`
- `/tmp/article-pipeline/01b-product-experience.md`

飞书同步只消费本轮已经生成的产品体验 JSON，不得重新调用上游抓取。

## 小红书安全边界

内容创作流默认永久禁用所有需要个人小红书登录态的能力，包括但不限于：

- `xhs search/read/comments/hot/feed`
- `xiaohongshu-mcp`
- 浏览器 Cookie 自动提取
- CDP 读取已登录小红书页面
- `~/.hermes/cookies/xhs.json` 和其他小红书 Cookie 文件

允许的输入只有：

- 用户主动提供的小红书链接、截图或导出内容。
- 无需个人登录态即可访问的公开搜索索引或公开网页摘要。

即使只搜索公开笔记，也不得借用用户浏览器或本地 Cookie。流程文档、主 Agent 路由和热点来源清单必须同时写入这一硬约束。

## 用户确认门

默认交互模式包含三个强制暂停点：

### 确认一：热点与选题

120 秒热点阶段结束后，输出 5 至 8 个候选及评分依据，等待用户选择。主 Agent 不得自动选题或提前进行深度研究。

### 确认二：角度

仅对用户确认的选题补充事实、历史内容和公开观点，生成 2 至 3 个角度及 SPOV 评分，等待用户选择。

### 确认三：定调与文章计划

输出标题方向、核心判断、目标读者、论点结构、证据支柱和平台形式，等待用户确认后才写正文。

“跑流程”“跑一次流程”“一条龙”“写一篇文章”默认都进入交互模式。只有用户明确使用“直接跑完”“全自动”“不用确认”等表达，才允许跳过前三个确认点。发布仍需遵循现有发布确认和权限规则。

## 热点评分修正

单个平台或单篇内容的高互动不能直接代表全网热点。

热点强度必须优先依据：

1. 真实热榜位置或平台热度字段。
2. 同一事件在不同来源中的独立出现次数。
3. 24 小时内的传播时间密度。
4. 来源覆盖层级和来源可信度。

若缺少真实榜位或跨平台证据，候选必须标注“垂直讨论”或“单平台高互动”，不得标注为高等级全网热点。小红书互动数据不再进入自动评分。

## 性能规则

- 热点阶段只加载主流程和热点阶段所需规则，不读取全部写作、质检和发布文档。
- Linkly、zvec、深度网页核验、评论研究和图片生成全部延后到用户确认选题之后。
- 来源抓取必须并行，禁止按平台串行执行。
- 同一来源失败最多尝试一次；不得在热点阶段反复重试。
- 服务健康时复用现有进程，不做无条件重启。
- 本轮抓取结果在本地处理、飞书同步和后续筛选中复用。

## 错误与降级

- 全局 120 秒截止时间优先级高于单源完整性。
- 任一来源超时后使用最近有效缓存，并显示缓存时间。
- 缓存超过来源允许的新鲜度时仍可用于“背景参考”，但不能参与时效和热度加分。
- 热点聚合主源不可用且没有缓存时，必须明确告知本轮无法形成可靠全网热点，不得用关键词搜索结果替代。
- 产品体验源不可用不影响热点候选输出，但必须单独标记产品池失败。

## 验证方案

### 性能测试

- 冷启动：本地服务未运行，120 秒内返回来源清单和候选。
- 热启动：服务健康且缓存存在，120 秒内返回；目标为 30 秒内。
- 慢源：人为让一个来源超过超时，验证其他来源不被阻塞。
- 重复同步：验证飞书同步不触发第二次产品抓取。

### 安全测试

- 扫描运行命令和日志，确认没有 `xhs`、`xiaohongshu-mcp`、小红书 Cookie 或 CDP 登录态调用。
- 用户未提供小红书材料时，产物中不得出现来自登录态小红书的数据。

### 交互测试

- “跑一次内容创作流”必须停在候选选题。
- 确认选题后必须停在角度。
- 确认角度后必须停在定调与文章计划。
- “直接跑完，不用确认”才允许自动继续。

## 发布范围

本次调整需要同步到：

- GitHub 仓库中的主流程、热点 Skill、相关规则和测试。
- Hermes Agent 本地对应 Skill。
- README 与 CHANGELOG。

发布前必须完成一次真实的两分钟热点抓取测试，并报告来源状态、总耗时、候选数量和是否发生缓存降级。
